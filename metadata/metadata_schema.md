# Схема метаданных для анализа 16S/ITS, shotgun и погодных событий

Одна TSV-таблица `metadata/samples.tsv` объединяет образцы и факторы среды.
Для каждой строки `sample_id` должен быть уникальным и совпадать с именем FASTQ,
исключая `_1.fastq.gz` / `_2.fastq.gz`, или именем Bracken без `.bracken`.
16S, ITS и shotgun обрабатываются отдельно, но могут ссылаться на одинаковые
строки `sample_id` при наличии нескольких библиотек одной пробы.

## Поля

| Поле | Обязательность | Смысл |
|---|---|---|
| `sample_id` | обязательно | Уникальный ID из латинских букв, цифр, `_`, `-`, `.` |
| `is_control` | обязательно | `TRUE` для отрицательного контроля, `FALSE` для биологической пробы |
| `site_id` | для событий | Идентификатор пункта отбора, одинаковый с `site_id` событий |
| `site_type` | желательно | `urban`, `rural`, `coastal`, `blank` и т. д. |
| `datetime_start` | для событий | Начало отбора, ISO 8601 `YYYY-MM-DDTHH:MM` |
| `datetime_end` | для событий | Конец отбора, тот же формат |
| `extraction_batch` | для контроля партий | Партия выделения ДНК |
| `library_batch` | желательно | Партия подготовки библиотек |
| `season` | необязательно | При отсутствии вычисляется по северному полушарию из даты |
| `temp_c` | для погоды | Средняя температура за окно отбора, °C |
| `rh_pct` | для погоды | Средняя относительная влажность, % |
| `wind_ms` | для погоды | Скорость ветра, м/с (метод агрегирования за окно задокументировать) |
| `precip_mm` | для погоды | Сумма осадков за окно отбора, мм |
| `pressure_hpa` | для погоды | Давление, гПа |
| `pm25` | необязательно | PM2.5, мкг/м³ |
| `pm10` | необязательно | PM10, мкг/м³ |
| `air_volume_m3` | желательно | Объём отобранного воздуха, м³ (сам по себе не делает read counts абсолютными) |

Минимальный набор для запуска анализа последовательностей — `sample_id`, `is_control`.
Для сравнения событий нужны дополнительные `site_id`, `datetime_start`, `datetime_end`.
Для регрессии/RDA требуются фактические числовые погодные поля.

**Внимание:** метеоданные должны быть привязаны к интервалу отбора, а не просто к календарному дню. Часовой пояс задаётся в `config.yaml`, смещение времени начала/конца нельзя игнорировать. Для южного полушария заполните `season` самостоятельно или адаптируйте расчёт.

## Таблица экстремальных погодных событий

`metadata/extreme_events.tsv`, одна строка на событие:

| Поле | Значение |
|---|---|
| `event_id` | Уникальный ID |
| `site_id` | Площадка отбора или `ALL` (для всех площадок) |
| `event_type` | Например `storm`, `heat`, `heavy_rain`, `cold` |
| `start` | Начало события, ISO 8601 в часовом поясе проекта |
| `end` | Конец события, после start |
| `criterion` | Порог и алгоритм выделения события |
| `source` | Метеостанция/архив/DOI/номер наблюдения |

События определяются **до** анализа микробиома на основании внешних метеорологических данных. Внутри Rmd выполняются только сопоставление с интервалом отбора, классификация `during`, `post_0_24h`, `post_24_72h`, `background` и анализ ассоциаций. Продолжительности лагов меняются в `project.lag_windows_hours`. Если время отбора отсутствует, при наличии файла событий используется `unassigned`.

## Отрицательные контроли

Контрольная проба — такая же строка в файле со значением `is_control=TRUE`; для неё метеополя могут быть `NA`. Рекомендуется хотя бы один отрицательный контроль на каждую партию экстракции и полноценный набор полевых бланков. Текущая автоматическая оценка `decontam` требует ≥2 контролей и ≥2 реальных образцов: при меньшем числе шаг пропускается. Бланки всегда исключены из экологических сравнений.

## Формат

Табуляция в качестве разделителя, UTF-8, десятичная точка, отсутствующие значения `NA`, идентификаторы без пробелов, даты в единой локальной временной зоне. Примерные строки из `*_template.tsv` **не являются экспериментальными данными**.
